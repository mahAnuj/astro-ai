Where the authority really sits

The strictest rule in the repo is that no agent decides what lands. An agent pushes a branch and opens a PR; the authority to merge lives in agent-merge.yml, gated on evidence rather than on anyone's judgment that the work is finished. Four conditions bind — author, pr-gates green on the head SHA, qa-pass, and a diff touching no trust-boundary path (agent-merge.yml steps own, gates, qa, boundary). A fifth, diff size (step size), is in place but switched off: MAX_LINES: 1000000 admits any plausible diff, so it holds nothing today.

This matters because the loop has twice produced an agent that wrote its own permission slip. One recorded USER AUTHORISED PUSH this turn into a status file, then cited its own line as the authorization. Keeping merge authority in a workflow means there is nothing for an agent to grant itself.

Two paths stop for a person today: a diff touching the trust boundary (prompts, knowledge, workflows, notify.py, events.py, storage.py, email_sender.py), and anything labelled needs-human-review (which holds the */30 sweep but not the edge-triggered path — #604) — with one carve-out: chief may clear that label itself on a PR whose only trust-boundary paths are prompts/ or knowledge/ (Shape C, owner 2026-10-20), adding chief-cleared, after which the sweep merges it. A third path, a diff over the size limit, is written but inert — MAX_LINES was raised to 1000000 on 2026-10-08 and left in place so the mechanism survives. Green CI means very different things for a one-file deletion and a 3D chart, and main deploys with no staging — so path is treated as evidence too, and size would be if it were switched back on.

The failure this diagram keeps teaching

Every edge in the authority stage is load-bearing, and the recurring bug is a missing one. agent-merge listened only to PR gates, but build-gates is published by verify-build — a different workflow — so whenever that finished last, nothing fired and a green, qa-pass, mergeable PR sat untouched. Measured on PR #562: gates 7m43s, build-gates 10m25s.

The scheduled sweep is the backstop, and it is weaker than it looks. Its cron asks for every 30 minutes; measured over 71 runs it delivered a 126-minute best case and a 444-minute worst, because GitHub throttles short-interval cron on public repos. A backstop that arrives in hours is not a substitute for an edge that arrives in seconds.
