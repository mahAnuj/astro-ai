# agent-measure's collectors run when agent-work completes (debounced), not on seven clock slots; verify-build skips its build for a measurements-only diff

- **Date:** 2026-11-09
- **PR / issue:** #811

## Why, measured

Measured 2026-11-05..09: eight `agent-measure` slots delivered ~4 runs a day at irregular times (the 21:00 analyst slot started 00:09-01:20Z), while what the collectors describe (loop outcomes, agent health, the Claude quota `chain_cycle.py` gates on) changes when a cycle finishes. Each run's own work was 1-7 min, but every measurement PR then ran `verify-build`'s full suite (~2 min) over a diff that cannot change it, and failed whenever `main` was red: #800 and #805 stacked that way behind #797. Now: `workflow_run` on `Agent work`, gated by `scripts/measure_due.py` (not within 60 min of the last measurement commit; not while a publisher measurement PR under 3 h old is open; scheduled and dispatched runs always due; fails open); one backstop slot `23 9 * * *` for a day with no cycle (keeps `claude_usage.json` inside chain_cycle's 36 h and `agents.json` inside the detector's 32 h); `measure.if` names `workflow_dispatch` explicitly, because `schedule == ''` also matches `workflow_run` and would have run the analyst after every cycle; concurrency no longer cancels, so a collector run cannot kill the analyst. `verify-build`'s scope step diffs against the merge base with origin/main and skips every later step only when the diff is non-empty and wholly under `measurements/` (the job still concludes success: `build-gates` is required); a push to `main` diffs empty and always builds. Left as is: the analyst slot runs after the 23:00 build cycle in practice, so that cycle plans on a day-old report; six cycles a day plus chaining make it minor.
