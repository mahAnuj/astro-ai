# scripts/verify_egress.py: a static allow-list of outbound hosts and network-client modules in src/

- **Date:** 2026-11-08
- **PR / issue:** #804

## Why, measured

#743 (split from #354). A loop-authored PR is merged on green gates and the repo is public, so one call to an unlisted host is an exfiltration path no gate saw; `TRUST_BOUNDARY` guards three files by name, not a new file that opens a socket. The gate parses `src/**/*.py` with `ast` and requires (1) every `http(s)://`, `ws(s)://` or `ftp(s)://` host in a `str` or `bytes` literal (f-string literal parts included, docstrings and comments skipped; scheme case-insensitive) to be in `ALLOWED_HOSTS`, where the host is the parsed AUTHORITY — after the last `@`, `:port` removed, ASCII-lowercased, trailing dot dropped, bracketed IPv6 and non-ASCII hosts reported as unlisted — and a literal with an `@` inside its authority (userinfo) fails on its own, with the host after the last `@` checked as well; every allowed host carries a `runtime`/`reference` kind and a reason, (2) every module importing a client (`httpx`, `urllib.request`, `openai`, `geopy`, `google.cloud`, `google.oauth2`/`google.auth`, `socket`, `ssl`, `subprocess`, ...) to be in `CLIENT_MODULES` with exactly those roots, and (3) no entry to be stale, so a deleted feature cannot leave a standing permission. Exit 2 on no `src/` or an unparsable file, never a pass. **Measured 2026-11-08 on aa2e62f:** 12 literal hosts (8 runtime, 4 reference) and 9 client files. Two findings: `www.drikpanchang.com` is `reference`, not runtime, because the only code literal is `festival_registry.SOURCE_URL_BY_YEAR`, which `/festivals` renders as a link, and `sankranti.py`/`adhik_maas.py` name it only in docstrings; and `routes/account.py` is a client the brief did not list (Google Sign-In's `id_token` check fetches Google's public certs from `www.googleapis.com`, host read from the installed `google.oauth2.id_token`). **Lets through, said plainly:** a host built from a variable inside a file already allowed a client, `ASTRO_AI_API_BASE`/provider env overrides, redirects, browser-side hosts and any host in a non-`.py` file under `src/`, dynamic imports, `asyncio` streams (`notify.py` and `routes/admin.py` import `asyncio` for non-network work, so it cannot be a root), `os.system`/`ctypes`/`multiprocessing`, protocol-relative `//host` and schemes outside http(s)/ws(s)/ftp(s). **QA round 1 on PR #804 found the host match bypassable and it was fixed:** `_HOST` was `https?://([A-Za-z0-9.-]+)`, so `https://api.groq.com@evil.com/x` captured the userinfo (allow-listed) while a client dials evil.com, `HTTPS://evil.com` and `b'https://evil.com'` were not scanned, and `https://évil.com` captured nothing. The class of defect was an allow-list of host CHARACTERS; each candidate is read through two views. The TIGHT view ends at `/ ? #`, whitespace, quote, `<`, `>` and gives the host, so prose ("see https://shubhagya.com for details") is no finding. The WIDE view ends at `/ ? #` only, as `urlsplit`, `httpx.URL` and `requests` do, and is read only for an `@`. **QA round 2 found the first fix still bypassable:** `https://api.groq.com @evil.com/x` exited 0 because the tight authority stopped at the space while httpx dials evil.com (verified 2026-11-08 with `urlsplit(...).hostname` and `httpx.URL(...).host` for space, `"`, `'`, `<`, `>`, NBSP, U+3000, NEL, VT, FF, FS, GS and backslash; httpx instead refuses VT/FF/FS/GS and tab/CR/LF with `InvalidURL`, urlsplit deletes tab/CR/LF). An `@` anywhere in the wide authority is a userinfo violation and the host after its last `@` joins the checked hosts; `#@` and `?@` are not in the authority and pass (pinned by a test). Tab/CR/LF are deleted and the literal scanned a second time. **Two fail-closed false positives, fixed by rewording:** "see https://shubhagya.com or mail a@b.c" (no `/ ? #` between the URL and an `@`) and a URL ending a line or an implicitly concatenated piece, which glues to the next text (`'https://api.groq.com<LF>.x/'` reads `api.groq.com.x`). `ssl` and `subprocess` joined `CLIENT_ROOTS` because no file in `src/` imports either (grep, 2026-11-08), so a `curl` shell-out now needs a reviewed entry. **Chosen:** static, because the tree is the only thing a PR changes and the gate must run in `pr-gates` with no workflow edit. **Rejected:** a runtime check (Cloud Run VPC egress is infrastructure, not reviewable in a diff) and a regex over raw text (it would flag the prose hosts in docstrings and comments and train people to widen the list). 37 tests on temporary trees, 34 rows in `scripts/mutations/2026_11_08_743_verify_egress.py` (each hand-applied to a copy and confirmed red on its own named test). 0 LLM tokens
