The history is worth keeping, because the next person to improve this file will otherwise repeat it — four QA rounds found four defects, each introduced by the previous round's fix: v1 posted `next = request.url.path`. On a /hi/ page that is /hi/rashifal, which forces Hindi, so choosing English wrote lang=en and re-rendered Hindi: a dead control that silently changed the reader's saved language. v2 real anchors between the two URLs. With a saved `hi` preference the ENGLISH url renders Hindi too, so the "English" anchor pointed at a page serving Hindi. Dead again, and a regression against main. v3 POST /lang with buttons. Correct server-side — and broken in a browser: base.html sets hx-boost="true" on , and a user-clicked submit DOES fire a submit event, so htmx intercepted it, swapped the body and left stale. The 108% Devanagari rule never applied and a screen reader kept the English voice. v4 v3 + hx-boost="false". Fixed that, and the `english_url()` call it used for `next` normalised the path, adding a second redirect hop to every switch on the 76 /learn/ URLs. So the ONLY change from main here is the `next` value, which is the one thing /hi/ actually requires: post the page's English path, and let `POST /lang` send the reader to the Hindi twin when they ask for Hindi.
