Two different caches. The response cache is this app's own: it lives in each Cloud Run instance and dies with it. The prefix cache is Groq's, and is opportunistic. Read Effective, not Hit rate. Groq returns no cache figure at all on a miss — not a zero — so Hit rate's denominator counts only the calls that hit and overstates the saving. Measured against live Groq 2026-10-17: 1 hit in 7 identical calls on gpt-oss-120b, which reads 97.5% as a hit rate and 13.9% as a saving. Effective is a saving over the Measurable calls, not over Fresh calls — compare those two columns before reading it as a share of the route's traffic. {% set ru = llm_stats.aggregate.prefix_cache.values() | map(attribute='reported_unmeasurable') | sum %} {% if ru %}{{ ru }} call(s) carried a cache report that Effective leaves out. The counter cannot tell its two causes apart, so read both. (1) A real report on a call this rule treats as unmeasurable. Most likely a non-Groq provider reporting its own cache, which is correct and needs no action — that figure is counted in Reported and in Hit rate, and is rightly kept out of Effective, because its silences follow a different convention. It can also mean the 128-token floor is too high for a Groq model. (2) An impossible report. The provider claimed more cached tokens than the prompt it came from, or a count that was not a non-negative whole number. That figure was discarded: it is in neither Hit rate nor Effective, and the call is not in Reported or Measurable, only in Fresh calls. This one does need attention — a route whose only reports were of this kind shows a dash in both rates. Do not add a non-Groq model to the reporting set to silence this: that would make its silences count as measured zeros under a Groq-derived floor, which is the original defect this panel was built to remove. {% endif %} {% if llm_stats.aggregate.prefix_cache_skipped_rows %}{{ llm_stats.aggregate.prefix_cache_skipped_rows }} stored row(s) were excluded as unreadable (written by an older schema, or keyed in a shape this page does not recognise), so their calls are missing from this table.{% endif %} {#- THE GAP, NAMED AND COUNTED. An Effective dash has four causes, so check which before concluding anything: a non-reporting model served every call; the prompts were under the minimum; the provider returned no usable usage block at all; or every report it sent was impossible and discarded.
